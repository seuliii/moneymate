# 4단계 — 실제 거래 기반 월별 통계

## 범위와 구현 방향

파트너의 Python/LLM 분석 서비스와 독립적으로 사용할 수 있는 C# 통계 및 Razor 대시보드를 구현했습니다. 실제 AI 호출은 이번 단계에 포함하지 않습니다. 기존 거래/카테고리/사용자 데이터 버전 테이블을 사용하며 추가 마이그레이션은 없습니다.

StatisticsService가 사용자 ID를 인증 정보에서 받아 DB에서 유형별 합계·카테고리 합계·최대 지출을 조회합니다. 여러 집계와 사용자 데이터 버전은 하나의 RepeatableRead 스냅샷에서 읽습니다. StatisticsCalculator는 기간·평균·비율·비교를 계산하며 HTTP API, 대시보드와 로그인한 메인 화면이 같은 서비스를 사용합니다.

## 제공 기능

- `/Dashboard`: 월 선택, 수입·지출·월간 수지, 일평균 지출, 카테고리 비중 막대, 최다 카테고리, 최대 단일 지출, 전체 및 카테고리 전월 비교.
- `/api/statistics/monthly?month=2026-09`: 인증된 사용자 본인의 월 통계 JSON. month 생략은 현재 한국 월이며 미래/잘못된 월은 400입니다.
- `/`: 로그인하면 현재 월 실제 합계 표시. 익명은 서비스 안내를 표시합니다. DB 접속 장애 시 홈 합계는 오류 안내를 표시하며 가짜 0원으로 대체하지 않습니다.
- 상단 통계 메뉴 및 대시보드에서 해당 월 거래 목록과 등록/최대 거래 수정으로 이동.

## 계산 기준

과거 월은 전체 달력 기간, 현재 월은 한국 날짜 기준 오늘까지 집계합니다. 거래일(DateOnly)을 사용하며 생성 시각을 거래 월로 쓰지 않습니다. 요청 시작 시 날짜를 한 번 고정합니다.

전월 비교는 과거 월이면 전월 전체, 현재 월이면 전월 같은 일자까지입니다. 해당 일자가 없으면 전월 말일로 제한합니다. 두 기간의 시작·종료·일수를 반환하고 일수가 다르면 안내합니다. 기간 차이를 자동 보정하지 않습니다.

합계와 수지는 long, 평균/비율은 decimal이며 소수 둘째 자리까지 AwayFromZero 반올림합니다. 일평균은 거래가 있는 날짜 수가 아닌 대상 달력 일수로 나눕니다. 월간 수지는 실제 계좌 잔액·저축액이 아닙니다.

전월 기록 없음은 no_previous_records이며 증감액·증감률은 null입니다. 전월에 수입만 있어 지출이 0이면 zero_previous_expense이며 증감액만 반환합니다. 정상 비교는 comparable입니다. 카테고리 비교는 이번/전월의 합집합으로 계산해 사라진 지출도 표시하며 분모가 0이면 증가율은 null입니다.

최다 카테고리와 최대 거래는 동률을 모두 반환합니다. 지출 0이면 두 배열은 비며 비중은 null입니다. 기록 없는 기간은 0원과 기록 없음 안내를 함께 표시합니다.

## API 주요 필드

month, asOfDate, isCurrentMonth, period(start/end/days), dataVersion, recordCount, income, expense, net, dailyAverageExpense, categories, topCategories, largestExpenses, comparison.

comparison은 status, previousPeriod, previousRecordCount, previousExpense, changeAmount, changePercent, differentDayCounts를 포함합니다. 응답은 캐시 금지입니다. 사용자 ID를 쿼리로 보내도 조회 소유자는 바뀌지 않습니다. largestExpenses의 제목은 사용자에게 표시하는 데이터이며 파트너 AI 입력 계약에 그대로 전달하지 않습니다.

## 검증

- 빌드 경고 0·오류 0.
- `dotnet run --project tests/StatisticsChecks`: 기획안의 수입 3,500,000원, 지출 154,500원, 수지 3,345,500원, 일평균 5,150원, 쇼핑 비중 77.67%, 전월 증가 28.75% 일치.
- 계산 검증: 월 경계, 현재 월/전월 기간, 윤년 및 2월 말일, 연도 전환, 한국/UTC 월 경계, 없는 기록과 지출 0 구분, 이전 월에만 있던 카테고리, 동률, 소수 반올림.
- `scripts/Test-DatabaseFoundation.ps1`: 별도 PostgreSQL/웹에서 실제 DB 집계, 통계 인증/소유자 격리, 잘못된/미래 월, 평균·최대 지출, 버전 일치, 거래 삭제 후 합계 갱신, 대시보드 응답 검증. 기존 회원·거래·동시성·CSRF·DB 제약 전체 통과.
- 실제 브라우저에서 대시보드와 메인 합계, 좁은 화면 배치, 오류 로그 없음 확인. 기존 확인용 계정의 수입 1,000,000원/지출 10,000원이 반영되며 실제 개발 거래를 추가·수정·삭제하지 않았습니다.
