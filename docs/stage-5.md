# 5단계 — 모의 분석·리포트와 파트너 계약

파트너 담당의 실제 Python/LLM 개발을 제외하고 웹 리포트 요청·저장·조회·캐시·갱신 표시를 구현했습니다. 기존 AnalysisReports 테이블을 사용해 새 마이그레이션은 없습니다.

## 구현

- /Reports 월 선택, 모의 생성/갱신, 이전 성공 결과, 요약·특징·변화·제안·근거와 데이터 한계 표시.
- POST /api/analysis/reports: 신규 201, 동일 기준 캐시 200. GET latest 및 소유자별 ID 조회 제공.
- 통계 스냅샷에서 partner 입력을 구성하며 개인정보 필드를 제외합니다. 최대 지출의 categoryCode를 통계에 추가했지만 DB 변경은 없습니다.
- 응답 필수 필드·버전·requestId·문장 길이·섹션 수·유효 근거 검증. 잘못된 응답은 저장하지 않습니다.
- 사용자·월 단일 진행 가드409, 날짜별 시도 한도429, 기준 변경 시 오래된 결과 표시. 캐시는 모의/HTTP 모드를 분리합니다.
- 선택 가능한 실제 HTTP 어댑터: Bearer 서비스 인증, 응답 크기 제한64KiB,25초 요청/60초 전체 제한,503/네트워크 최대1회 재시도.
- 초기 실행은 Mock이며 실제 AI 데이터 전송과 외부 서비스 호출은 하지 않습니다. 실제 연동은 파트너 준비 후 검증합니다.

## 파트너 공유 파일

docs/api/partner-contract-v1.md: 역할·계약·인증·오류·기간/수치·캐시·제한·실행 설정 및 합의 항목.

docs/api/examples/monthly-request.json 및 monthly-response.json: 가상 데이터이며 C# 계약 검증 도구가 생성합니다.

## 검증 도구

`dotnet run --project tests/AnalysisChecks`: 개인정보 제외, 근거/필드 검증, 하루 한도·가드, HTTP 경로·인증·재시도 시 requestId 유지, 잘못된 JSON·크기 초과·시간 초과·모의 응답.

scripts/Test-DatabaseFoundation.ps1: 기존 회원/거래/통계 회귀에 리포트 API/폼 저장·캐시·동시 생성409·CSRF·소유권·오래된 결과·빈 월 거절·이전 성공 결과 유지 검증을 포함하며 통과했습니다.

빌드는 경고0·오류0, AnalysisChecks 및 StatisticsChecks 통과입니다. 게시 결과에서 appsettings.Local.json 제외를 확인했습니다. 실제 브라우저에서 확인용 계정의 모의 리포트 1건 생성·저장·조회와 실제 합계 표시를 확인했으며 기존 거래를 변경하지 않았습니다. 근거는 내부 ID 대신 사람이 읽는 통계명·금액으로 표시합니다.

## 남은 연결 및 업로드

실제 Python/LLM의 의미 정확성·지연·인증 호환성은 아직 검증하지 않았습니다. 현재 시도 한도와 진행 가드는 단일 프로세스용이며 운영 전 공유 저장소 검토가 필요합니다.

5단계 검증 후 GitHub 업로드를 진행사항에 포함합니다. 저장소 주소/공개 범위를 확인한 후 소스·문서·가상 예제만 올리고 로컬 비밀번호 파일·캐시·빌드/게시 폴더·실제 거래 데이터는 제외합니다. 현재 요청은 5단계 로컬 개발이며 아직 GitHub 업로드를 수행한 상태는 아닙니다.
